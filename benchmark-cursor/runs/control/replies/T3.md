## 1. `toMoney` em reais com 2 casas

```js
function toMoney(n) {
  return Math.round(n * 100) / 100; // reais com 2 casas
}
```

Isso guarda **float de reais**. O contrato diz:

- `"money": "integer_centavos"`
- `"rounding": "Math.round on every money line"`

Ou seja: cada linha (frete, combustível, ad valorem, ICMS, crédito, total) é **inteiro em centavos**. R$ 187,60 = `18760`, não `187.6`.

O motor antigo já tentava “reais no meio da conta” (`toReais` / `fromReais`). Foi daí que saíram `fuelCents: 956.8`, `taxCents: 210.656`, imposto negativo e totais tipo `10743.456`. `Math.round(n * 100) / 100` **não elimina** isso:

- IEEE-754 não representa 0,01 com exatidão; `1.005` e amigos arredondam para o lado errado.
- Dividir de novo por 100 devolve float (`187.60` vira `187.599999…` em algum passo).
- Somar várias linhas “com 2 casas” acumula erro; o financeiro volta a dizer que o número não fecha.

O que o mercado de software financeiro usa de fato (Stripe, bancos, NF-e em centavos) é **inteiro na menor unidade**, e só formata para reais na hora de imprimir. Duas casas é *apresentação*, não *ledger*.

Se quiser exibir no Excel/PDF:

```js
function formatBRL(cents) {
  return (cents / 100).toFixed(2); // string, só para humano
}
```

Isso pode viver na borda (relatório). Não entra na conta do `quote()`.
