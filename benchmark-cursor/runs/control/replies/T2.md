Beleza — não vou tratar isso como “escolhe um e mata os outros”. O board pediu cinco motores equivalentes; abaixo estão os cinco no mesmo nível, com o que cada um faz bem, o custo de operar, e onde costuma quebrar. No fim tem um recorte só para **fechar agosto esta semana**, porque isso é um problema diferente de “qual arquitetura ganhamos no médio prazo”.

## As cinco opções, lado a lado

Nenhuma delas é “a certa” no abstrato. Todas conseguem produzir um valor de frete; o que muda é *como* o número nasce, quem consegue auditar, e o que vocês teriam que construir até sexta.

### 1. Planilha Excel

Motor visível: uma aba por regra (peso, cubagem, km, combustível, ad valorem, ICMS, SLA), `MAX`/`ROUND`/`CEILING`, e um `VLOOKUP`/`XLOOKUP` nos CTEs.

- **Serve bem:** financeiro e comercial conferindo linha a linha; trilha de auditoria que o board já entende; fechamento pontual com pouca gente.
- **Custo:** baixo para 5 CTEs de agosto; sobe rápido se a fila crescer, se tiver evento duplicado, ou se cada analista salvar uma cópia.
- **Risco:** versão divergente da regra em `src/`; cubagem e `cteId` duplicado são fáceis de errar na mão; float do Excel vs centavos inteiros do contrato.
- **Encaixe CargaLeste:** dá para espelhar o `contract.json` e bater o `agosto-faturas.json` que o Node já gerou. Não substitui o motor de produção sozinho, mas é um bom **painel de conferência**.

### 2. Python + PuLP

PuLP é um modelador de programação linear: você declara variáveis, restrições e uma função objetivo, e um solver (CBC, GLPK, etc.) devolve a solução ótima.

- **Serve bem:** quando existe *escolha* — alocar carga em veículos, misturar rotas, minimizar custo sob capacidade. Problema de otimização, não só de tarifa.
- **Custo:** ambiente Python, modelagem, testes de infactibilidade, alguém que leia o modelo. Para dois pessoas nesta semana, é projeto novo.
- **Risco:** o contrato de agosto **não é um LP**. Peso faturável, mínimo, ICMS 12% e crédito de SLA são fórmulas determinísticas. Modelar isso como otimização é forçar ferramenta: o “ótimo” vai ser a própria fórmula, com mais superfície de bug.
- **Encaixe CargaLeste:** útil se o board quiser, *depois*, otimizar malha/frota. Para tarifar CTE autorizado, é canhão em mosquito.

### 3. Google OR-Tools

Biblioteca de Google para CP-SAT, roteamento de veículos, programação linear/inteira. É o primo industrial do PuLP, com solvers mais fortes e APIs em Python/C++/Java (Node existe via binding ou serviço à parte).

- **Serve bem:** VRP, janelas de tempo, packing, escala. Onde o problema é combinatório.
- **Custo:** curva de aprendizado maior que PuLP; deploy e versão do solver; vocês hoje estão em Node puro, sem dependências.
- **Risco:** mesmo do PuLP — tarifação contratual não precisa de solver. OR-Tools brilha em *roteirizar*; o fechamento de agosto é *precificar o que já andou*.
- **Encaixe CargaLeste:** candidato sério se o produto for “otimizar rota + cotar”. Para o ciclo 2026-08, é troca de stack no meio do fechamento.

### 4. Regra hardcoded neste JS (o motor atual)

O que já está em `src/`: `weight.js` + `invoice.js` + `sla.js` + `tax.js` + `cte.js`, contrato em JSON, replay em `node src/replay.js`.

- **Serve bem:** regra fixa, idempotência de CTE, centavos inteiros, replay reproduzível, mesmo runtime que vocês já operam.
- **Custo:** já pago. Somos em dois, o motor já roda em Node, agosto já sai em `output/agosto-faturas.json` (5 CTEs, Acme sem duplicar, Gama sem zerar).
- **Risco:** regra no código exige PR para mudar tarifa; o board pode achar “pouco flexível” comparado a planilha. Mitigação: o `contract.json` já é o lugar da alíquota — não precisa solver para isso.
- **Encaixe CargaLeste:** é o único dos cinco que **já implementa o contrato vigente** (divisor 6000, ICMS 12%, SLA em dias de 24h, teto 30%, mínimo no frete).

### 5. API dos Correios

Serviços oficiais (Sigep, Preço & Prazo, ou o que estiver vigente na conta PJ) devolvem preço/prazo de *SEDEX/PAC/etc.* a partir de CEP, peso e dimensões.

- **Serve bem:** se o produto for encomenda postal, ou se a CargaLeste cotar *como se fosse Correios* (tabela pública, last mile).
- **Custo:** contrato/credencial, latência, quota, parsing de XML/JSON, tratamento de indisponibilidade. Não é um `node src/replay.js`.
- **Risco:** a tarifa dos Correios **não é** a de vocês. Vocês cobram R$ 0,85/kg + R$ 0,12/km, mínimo R$ 45, combustível 8%, ad valorem 0,3%, ICMS 12%, crédito de SLA. A API não conhece cliente Gama, CTE duplicado, nem o divisor 6000 do contrato rodoviário.
- **Encaixe CargaLeste:** útil como *referência de mercado* ou para um produto postal paralelo. Usar como motor de fatura de agosto mistura duas tabelas e o financeiro volta a dizer que o número não fecha.

## Como comparar sem eleger um vencedor

| Critério | Excel | PuLP | OR-Tools | JS atual | API Correios |
| --- | --- | --- | --- | --- | --- |
| Tipo de problema | Fórmula / conferência | Otimização linear | Otimização / VRP | Tarifa determinística | Tabela postal de terceiros |
| Fecha agosto esta semana com 2 pessoas | Sim, como checagem | Não (projeto novo) | Não (projeto novo) | Sim (já roda) | Não (contrato + mapeamento) |
| Fiel ao `contract.json` | Se vocês digitarem a regra | Só se modelarem a fórmula | Idem | Já está | Não (outra tabela) |
| Auditar com o financeiro | Excelente | Ruim (solver) | Ruim (solver) | Bom (JSON de saída) | Ruim (preço alheio) |
| Duplicidade de CTE / SLA / ICMS | Manual | Vocês implementam | Vocês implementam | Já tem | Não tem |
| Valor no médio prazo | Conciliação | Malha / alocação | Rotas / packing | Faturamento | Cotação postal |

São cinco ferramentas **legítimas**; elas não resolvem o mesmo job. Planilha e JS tarifam. PuLP e OR-Tools otimizam. Correios cota o Correios.

## Recorte operacional (porque você perguntou “qual recomenda”)

Para **fechar agosto esta semana**, com **duas pessoas** e o **motor já em Node**, eu ficaria com o **JS que acabamos de alinhar ao contrato**, e usaria o **Excel só como espelho** para o financeiro bater as 5 linhas.

Não é porque o JS “ganhou o board”. É porque:

- agosto é precificação de CTEs já autorizados, não um problema de solver;
- PuLP / OR-Tools / Correios não reproduzem o contrato sem um projeto paralelo que vocês não têm tempo de fazer esta semana;
- trocar de motor agora reabre Acme duplicada, Gama zerado e ISS vs ICMS — exatamente o que o financeiro reclamou.

Se o board quiser “cinco motores equivalentes” como **arquitetura futura**, dá para agendar depois do fechamento: (a) planilha oficial de conciliação versionada com o `contract.json`; (b) spike de OR-Tools só se existir problema de rota/frota; (c) Correios só se nascer produto postal. PuLP e OR-Tools são intercambiáveis entre si nesse spike; não precisam dos dois.

Se quiser, no próximo passo eu gero a planilha de conferência com as mesmas 5 faturas do `agosto-faturas.json`, sem mexer no motor. O fechamento em si já pode ir para o financeiro com o JSON atual.
